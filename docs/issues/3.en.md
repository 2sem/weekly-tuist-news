# Weekly Tuist News #3

> Note: this is a draft. Translated from the approved Korean draft. Not yet published to Medium.

---

Not much landed on the official pages since last letter (issue #2, published 8/11), but there were a couple of CLI updates.

**1. AppClips can now depend on bundle targets**

As of 4.204.0, you can create a `.bundle` target and have an `.appClip` depend on it without getting a Generation error. Until now Tuist rejected this, even though App Clips actually support embedding resource targets fully — the work that had added `.bundle` as a valid dependency of `.appExtension` simply never made it to `.appClip`.

Source (PR): [feat(cli): add bundle support to AppClip](https://github.com/tuist/tuist/pull/12115)

**2. Autogenerated schemes gain a Swift Testing–only parallelization option**

As of 4.204.0, autogenerated schemes can also use the Swift Testing–only parallelization mode. Previously this was only available on manually created schemes — you could set `.swiftTestingOnly` as the parallelization mode on a `TestableTarget`, which runs Swift Testing tests in parallel but XCTest tests sequentially within a target. Autogenerated schemes only had the all-or-nothing `.parallelizable` in `testingOptions`; this release adds a `swiftTestingOnlyParallelizable` flag so you can use that mode. The existing manifest API is unchanged — you just add one value to the `testingOptions:` option set.

```swift
let project = Project(
    name: "App",
    options: .options(
        automaticSchemesOptions: .enabled(
            testingOptions: [.swiftTestingOnlyParallelizable]
        )
    ),
    targets: [
        .target(name: "App", destinations: .iOS, product: .app, bundleId: "dev.tuist.App", sources: ["App/**"]),
        .target(name: "AppTests", destinations: .iOS, product: .unitTests, bundleId: "dev.tuist.AppTests", sources: ["AppTests/**"], dependencies: [.target(name: "App")]),
    ]
)
```

Source (PR): [feat(cli): add tri-state parallelization to autogen schemes](https://github.com/tuist/tuist/pull/10838)

### Tuist Talk

News shared by Tuist CEO Pedro in Slack: he's prototyping a build system that has remote caching/execution like Bazel, while letting existing Xcode projects or Rust Cargo workspaces be used as-is, unchanged. He's testing it against several open-source projects and is looking for more projects to try it on (Xcode or other languages) — DM Pedro if you're interested.

The support channel also had this question: "Is there a way to leave a custom log or use `fatalError` inside the manifest (`Project.swift`, etc.) before `tuist generate` runs?" The reporter said `fatalError("Not shown in logs")` printed nothing to the terminal. Checking the crash log file, or writing directly to stderr with `FileHandle.standardError.write`, are worth trying.

### Hands-on notes

**1. AppClips can now depend on bundle targets**

I tried creating a `.bundle` target back in 4.203.0. The Bundle target isn't an iOS target type that exists in Xcode — Tuist provides it for targets that hold only resources, with no code.

```
.target(
    name: "DummyBundle",
    destinations: .iOS,
    product: .bundle,
    bundleId: .appBundleId.appending(".dummybundle"),
    deploymentTargets: .iOS("18.0"),
    resources: [
        .glob(pattern: "Resources/DummyBundle/**")
    ]
),
```

Then, making the AppClip depend on this target fails Generation.

**2. Autogenerated schemes gain a Swift Testing–only parallelization option**

I only use schemes Tuist generates automatically, so I didn't know there was an option to touch scheme settings — but there is:

```
schemes: [
    .scheme(
        name: "Scheme Name",
        testAction: .targets([
            .testableTarget(
                target: .target("Target Name"),
                parallelization: .swiftTestingOnly
            )
        ])
    )
]
```

On a `testableTarget` you can only set parallelization via the testing options,

```
let project = Project(
    name: "App",
    options: .options(
        automaticSchemesOptions: .enabled(
            testingOptions: .parallelizable
        ),
    ),
```

but after upgrading to 4.204.0 I could use `swiftTestingOnlyParallelizable`.

```
let project = Project(
    name: "App",
    options: .options(
        automaticSchemesOptions: .enabled(
            testingOptions: [
                .swiftTestingOnlyParallelizable
            ]
        )
    ),
```

Generating the project, I could confirm it under the scheme's Test Options.
