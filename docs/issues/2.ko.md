# Weekly Tuist News #2

> **DRAFT — 검토 중.** 아직 승인 전이며 영어 번역/최종 포맷 이전 단계입니다. 내용은 언제든 바뀔 수 있습니다.

지난 주 변경 사항이 별로 없어서 4.203.0 내용을 추가했습니다.

**1. 명령 실행 결과 Export 옵션 추가**

[4.203.0](https://github.com/tuist/tuist/releases/tag/4.203.0)부터 수행 결과를 원하는 위치에 export할 수 있습니다.
지금까지는 CI 결과에서에서 대시보드 URL을 얻으려면 로그를 읽어야했습니다. 이제 `--run-report-path` 옵션이 추가되어, 실행 결과를 JSON으로 저장할 수 있습니다. 빌드와 테스트를 동시에 하는 커맨드라면 두 URL이 모두 리포트에 포함됩니다. 환경 변수(`TUIST_RUN_REPORT_PATH`)로도 설정할 수 있습니다.

```json
{
  "runId": "...",
  "status": "success",
  "runURL": "https://tuist.dev/acme/app/runs/123",
  "testRunURL": "https://tuist.dev/acme/app/tests/456",   // tuist test | tuist xcodebuild test
  "buildRunURL": "https://tuist.dev/acme/app/builds/789", // tuist xcodebuild build | tuist xcodebuild test
  "testRuns": [
    { "scheme": "App", "succeeded": true, "totalTests": 10, "skippedTests": 2, "ranTests": 8, "failedTestNames": [] }
  ],
  "buildRuns": [{ "scheme": "App", "succeeded": true, "durationInSeconds": 432 }]
}
```

원문: [Get a run's dashboard URLs as JSON, on any CI provider](https://tuist.dev/changelog/2026.07.17-run-report-json)

**2. 네트워크 재시도 정책 옵션 추가**

[4.203.0](https://github.com/tuist/tuist/releases/tag/4.203.0)부터 네트워크 재시도 횟수를 10번 까지 설정할 수 있습니다.
지금까지는 재시도 횟수가 3회로 고정되어있었지만(타임아웃을 늘리면 한 번의 지연이 최대 네 번의 긴 대기로 이어질 수 있었음) `TUIST_HTTP_MAXIMUM_RETRY_COUNT` 환경 변수로 횟수를 설정할 수 있고, `TUIST_HTTP_RETRY_BASE_DELAY_IN_MILLISECONDS`로 기본 딜레이를 최대 30000ms까지 설정할 수 있습니다.

참고로 기존 기본 딜레이가 원래 의도(100ms)보다 훨씬 짧은 약 1ms로 동작하던 버그도 이번에 같이 수정됐습니다. 재시도마다 딜레이가 두 배로 늘고 무작위 지터가 더해져, 네트워크 장애 시 클라이언트들이 한꺼번에 재시도하는 상황을 피할 수 있습니다.

원문: [Tune network retries for slow or congested connections](https://tuist.dev/changelog/2026.07.21-configurable-network-retries)

**3. Quarantine/Flaky 테스트 정렬 기준에 "분류 시기" 추가**

[8월 4일](https://tuist.dev/changelog/2026.08.04-sort-quarantined-flaky-tests-by-marked-time)부터 대시보드에 격리 및 불안정한 테스트 정렬 기준이 새로 추가되었습니다.
격리 테스트 목록에는 "Quarantined at"이, 불안정한 테스트 목록에는 "Marked flaky at"가 정렬 기준에 추가되어 가장 오래 방치된 테스트를 찾거나, 최근에 무엇이 격리됐는지 시간순으로 확인하기 쉬워졌습니다.

(CLI 버전과는 무관한 대시보드 기능입니다.)

### 도입 후기

#### `--run-report-path` ####
먼저 추가 parameter가 필요하지 않아 가장 쉬운 `tuist test`에 --run-report-path를 추가해서 실행해봤습니다.
`mise x -- tuist test --run-report-path test-result.json`

test-result.json을 열어보면:
```json
{
  "buildRunURL" : "https://tuist.dev/gamehelper/gersanghelper/builds/build-runs/823fd1d9-1be5-4e0a-ae61-8edbdde53a41",
  "buildRuns" : [

  ],
  "runId" : "30618FEF-D74C-47B8-AE8B-D2364C94CB2C",
  "runURL" : "https://tuist.dev/gamehelper/gersanghelper/builds/build-runs/823fd1d9-1be5-4e0a-ae61-8edbdde53a41",
  "status" : "failure",
  "testRunURL" : "https://tuist.dev/gamehelper/gersanghelper/tests/test-runs/41a173bb-e446-4d63-b203-56c98b7785f1",

      "failedTestNames" : [
```

#### Quarantine/Flaky 테스트 정렬 기준 ####

대시보드의 테스트에서 격리된 테스트를 열고 정렬 기준을 눌러보니 'Quarantined At'가 추가된 것을 확인할 수 있었습니다.

(Quarantined At 스크린샷)

테스트 데이터가 없어서 직접 정렬에 사용해보진 못 했지만 한국어 설정 시 아직 번역되지 않은 것으로 나타났습니다.
(한국어로 하면 '격리 시기' 정도가 될 수 있을 것 같네요.)

마찬 가지로 불안정 테스트에서는 'Marked flaky at'으로 확인 되었습니다.

(Marked flaky at 스크린샷)

이것도 아직 번역되지 않은 상태였습니다. 번역하면 '불안정으로 표시된 시기'가 될 것 같은데 둘 다 '분류 시기'로 해도 될 것 같네요.
