# Weekly Tuist News #7

> Note: this is a draft. Translated from the approved Korean draft. Not yet published to Medium.

---

This issue covers one security patch, plus CLI 4.216.0 and 4.217.0. If you use the CLI, I'd suggest checking your version first this time.

**1. TLS certificate verification security update: CLI 4.214.1 (10/30)**

This is a security update in response to the leak of an eMudhra certificate key. It rejects certificate chains built with the affected key and also refreshes the bundled certificate store. Normal certificate and hostname verification stays on, and separate private certificate authorities are still supported.

Sources: [changelog 2026.10.30](https://tuist.dev/changelog/2026.10.30-tls-certificate-security-updates), [4.214.1 release notes](https://github.com/tuist/tuist/releases/tag/4.214.1)

**2. CLI 4.216.0 (11/9): more test and coverage options**

A release heavy on features.

- `tuist test` supports target tag selectors.
- `tuist test --coverage-output-path` writes each run's coverage as LCOV.
- Generated test plans support coverage targets and can pin locales. Existing compatibility is preserved.
- The module cache supports simulator and device destinations.
- Cargo test sharding and quarantine, and expanded Cargo caching (shared REAPI, chunk reuse), arrived.
- Desktop and CLI previews were added.

Fixes include storing cached binaries for targets whose sources hold no code or share one file, serializing shared credential refreshes, and hardening certificate trust across client integrations (the same theme as item 1).

Source: [4.216.0 release notes](https://github.com/tuist/tuist/releases/tag/4.216.0)

**3. CLI 4.217.0 (11/16): coverage-based test selection and sandbox**

- Coverage-based test selection is here.
- `tuist test` can select a destination.
- `tuist build bazel` reads Bazel invocations, and `tuist bazel setup --remote-execution` discovers remote execution.
- A sandbox API, MCP tools, and `tuist sandbox` commands were added.
- Cargo caching became relocatable, and CLI previews are published from pull request builds.

There are many fixes too. For example: caching package targets that declare thousands of SwiftPM headers, linking the C++ standard library into clients of C++ package targets, and making cached macro consumers relocatable under Xcode compilation caching.

Source: [4.217.0 release notes](https://github.com/tuist/tuist/releases/tag/4.217.0)

**Tuist Talk: after upgrading to 4.214.1, installs break**

On the public [Tuist Slack](https://tuist-community.slack.com/archives/C018QG7U7SN/p1793620002488369), a user asked about problems after the CLI 4.214.1 update that was announced as required. The question was whether 4.214.1 started using [SwifterPM](https://tuist.dev/blog/2026/07/16/swifterpm), and if not, how to turn it off and check.

The user found `TUIST_USE_SWIFTERPM=0` and tried turning it off, and said SwifterPM seems unable to handle binary releases hosted on their company JFrog registry. But I replied that SwifterPM was already the default before 4.214.1, and this user was on 4.202.2. `tuist install` has used SwifterPM by default since 4.202.0. So something else that changed in 4.214.1 may be the cause.

The cause is still unknown. I suggested leaving the error in the thread so the Tuist team could see it, but the user said something else urgent came up and they couldn't continue testing. 4.214.1 is the TLS security patch, so read this together with item 1. If you use an internal registry or proxy, I'd suggest testing before upgrading.

Source: Slack thread
